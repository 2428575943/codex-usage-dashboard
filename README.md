# Codex 额度守护 0.2.0

Windows 10/11 x64 社区工具。0.2 使用 Codex 官方 **UserPromptSubmit 提交前检查**，在消息发送给模型之前执行额度规则，不再依赖切换启动菜单来拦截模型。

## 使用

1. 安装 `codex-quota-guard-0.2.0-setup.exe`。安装器自带 Python，当前用户安装，无需修改安全软件。
2. **首次启用请打开 Codex 设置 → Hooks，审核“正在检查 Codex 额度与模型”的检查。** 软件不会代写审核通过状态或绕过信任检查。
3. 审核操作会热更新已加载的本地聊天。之后每次提交都按该次实际选择的模型检查，无需重启 Codex，旧聊天也适用。
4. 不允许的模型会被明确阻止提交。留在同一聊天，切换到允许的模型后重新提交即可；工具不会冒充已经自动切换了模型。

## 规则

| 官方 5 小时剩余 | 允许提交的模型 |
|---|---|
| 大于 30% | GPT-6.1 Terra、GPT-6.1 Sol、GPT-6 Luna；GPT-6.2 Sol 的准确型号已预留 |
| 15% 至 30%（含两端） | GPT-6.1 Terra、GPT-6 Luna |
| 小于 15% | GPT-6 Luna |
| 无法确认额度 | GPT-6 Luna |

内部自动安全审核不作为供用户选择的模型处理，保留内部审核用途。

每次提交前读取官方账号额度；并发聊天最多共享 **5 秒**的同账号查询缓存，避免同时反复请求。登录变化、已到重置时间或缓存过期后重新查询。查询失败不会沿用高额度授权，只保留 Luna。已知脚本异常返回明确的阻止决定。

## 已验证的效果

用真实 Codex 0.167 组件、本版检查脚本和本地模型请求记录服务完成了 13 个场景。测试聊天先调用模型，再安装和审核检查；全程同一个后端进程和聊天，没有重启。额度模拟从 40% 降为 20% 后 Sol 请求被阻止，再降至 10% 后 Terra 请求被阻止；Luna 可提交，恢复 80% 后 Sol 又可提交。被阻止场景的模型服务请求数为 **0**，显式指定 Astra 同样被阻止。

上述额度是隔离环境固定数据，没有使用真实凭据或远程推理。证据见 `validation-live-admission.json`。桌面版实际安装代码中的 Hook 审核使用 `config/batchWrite` 和 `reloadUserConfig: true`；本工具只读研究了此行为，没有修改应用资源。

## 准确的生效范围

- **已有本地聊天的下一次提交前检查**，包含该次显式覆盖的模型；审核后额度变化不需要重启。
- 已经发送的请求无法追回。同一轮内部工具续写、自动续轮或重试没有逐次拦截。官方 PreModelRequest 只供诊断，不能通过返回值阻止请求，因此没有把它包装成强制拦截器。
- 子任务、远程或云端编排不应假定都经过 UserPromptSubmit；不宣称覆盖这些路径。
- Hook 被禁用、未审核、加载失败、超时或进程被外部终止时，Codex 可能继续放行；这是个人额度管理工具，不是不可绕过的系统安全边界。
- 稳定模型目录与轻度／中／高强度菜单是辅助配置，菜单显示刷新可能需要重新加载客户端，提交拦截无需靠菜单刷新。已有聊天显式选择的思考强度没有逐请求限制。
- 官方额度有查询与结算延迟，其他设备也可能同时消耗。“实时”指每次提交检查、共享缓存最多 5 秒，不保证跨设备零延迟。

## 隐私、停用和恢复

Hook 输入可能含用户消息。本工具只在内存中读取模型和事件类型，不保存消息、聊天正文、transcript 内容或登录凭据，不上传它们；只保留一条本地检查回执与本地额度缓存。

原配置和原 Hooks 文件会备份。卸载或“停用并恢复”移除自己的检查，保留其他检查和用户后续改动。退出托盘只退出后台窗口；**已审核的提交检查仍由 Codex 执行**。要停用，请使用“停用并恢复”或在 Codex 的 Hooks 设置中禁用。

与原 Codex Usage Monitor 分开运行，不修改原统计数据库、采集器或 Render 服务。

## 自动更新和兼容性

GitHub 分发，最多每 24 小时检查一次，包括失败与重启。只接受固定 Ed25519 公钥签名、相符 SHA-256 的递增版本。新的 Hook 必须由用户审核，不代写信任状态。

不修改 Codex.exe、ChatGPT.exe 或应用资源，不注入进程、不关闭杀毒软件。不能保证所有杀毒软件不误报，也不能保证所有未来 Codex 版本。更新验签不等于 Windows 发布者签名。

`python -m unittest discover -s tests -v` 验证策略、缓存、并发查询、恢复与签名。

`tests/verify_component_admission.py` 使用指定 Codex 二进制、Python 运行时和隔离目录运行真正的请求拦截测试。信任状态只写入测试自己的 CODEX_HOME，不修改真实用户的审核状态。

构建：`python build.py --runtime-source <Python目录> --iscc <ISCC.exe>`。
